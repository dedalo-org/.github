# Support

- **A bug, or something that does not work as documented** — open an issue on
  the repository in question. Include the version or commit, what you expected,
  and what happened.
- **A question about how to use something** — open a discussion, or an issue if
  the repository has discussions turned off. Questions that turn out to be
  documentation gaps are treated as bugs in the documentation.
- **A security vulnerability** — do not open an issue. Follow
  [SECURITY.md](SECURITY.md).
- **A change you want to make** — read [CONTRIBUTING.md](CONTRIBUTING.md)
  first; for anything larger than a fix, open an issue before writing the code
  so the design can be agreed on.

These are volunteer-maintained projects. There is no support SLA, and the
fastest path to a fix is usually a pull request with a failing test.
